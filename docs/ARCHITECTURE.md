# 架构说明

请求首先进入 `WorkspaceAgent`，由它选择受限工具。`WorkspaceGuard` 是路径信任边界，所有交互式文件工具必须通过它解析相对路径。`ProjectAnalyzer` 负责采集可核验指标并产生 `Finding`；报告层只负责表现，不改变分析结论。`ReportStore` 使用同目录临时文件和原子移动，每份归档带毫秒时间戳与随机唯一后缀，同时避免中途中断留下半份报告和快速连续运行同名。只有文件系统明确不支持原子移动时才降级为普通移动。

当前分析是确定性规则系统，而不是大语言模型。这样可以离线运行、重复验证，也能明确解释分数。未来若接入模型，只允许模型总结已经采集的证据，不允许模型绕过路径保护直接访问文件。

待办统计只识别源码注释中的 `TODO`、`FIXME` 和 `HACK`，不会把 README 中的术语说明或字符串字面量误判为任务。`TodoScan` 在统计总数的同一遍读取中收集最多 10 个相对路径和行号，不把源码文本复制到报告。

`DailyRunService` 是无人值守入口，一次分析后同时保存人类可读报告、机器可读健康报告、行动计划与历史快照，避免多次扫描产生不一致结果。CLI 用稳定退出码区分业务门禁失败、参数错误和运行故障。
完成清单 `latest-run.json` 由 CLI 在该轮所有静态产物，以及可选构建证据落盘后最后写入。它是状态目录的机器可读提交标记，并记录与 CLI 一致的预期退出码。

CLI 在整个日检编排期间持有 `StateRunLock`，锁粒度是规范化后的状态目录。锁由操作系统随通道关闭释放，进程异常退出不会留下逻辑死锁；持久锁文件不能被当作运行中标志。

机器接口由 `JsonReportWriter` 提供，当前契约版本为 1。实现不引入运行时 JSON 依赖，并对来自文件系统的字符串执行完整 JSON 转义，避免项目名或证据文本破坏输出结构。

`ActionPlanJsonWriter` 与 Markdown 规划共用同一 `ActionPlanner`，因此排序、豁免过滤和恢复分估算不会在人类与机器接口间分叉。

`AnalyzerConfig` 从项目根目录加载受限配置。额外忽略项只接受单段目录名，扫描文件数、文本大小和待办阈值都有上下界，以防错误配置造成越界访问或无界资源消耗。

每个 `Finding` 都有稳定的小写规则 ID。`rules.disabled` 只在发现加入结果前做精确 ID 匹配，既保留指标采集，也避免依赖本地化文案进行脆弱抑制。

`ScoreWeights` 随 `ProjectProfile` 一起进入报告和 JSON，不使用隐藏的全局状态。行动计划的预计恢复分值与该次扫描实际采用的权重一致。

`RuleWaiver` 绑定稳定规则 ID、负责人、原因和到期日。有效豁免仍保留在 Finding 和所有报告格式中，但不参与扣分与行动队列；过期豁免自动失效，原始风险恢复正常行为。

组合分析通过 `AnalyzerConfig.loadScopes(workspace, project)` 分层加载配置。Java Properties 后加载层覆盖前一层，因此项目可以覆盖工作区默认标量与规则配置；单项目分析只建立一个配置作用域。

`HtmlReportWriter` 生成不依赖脚本、字体或 CDN 的离线单文件看板。所有来自项目的文本先进行 HTML 实体转义；`HtmlReportStore` 与其他状态写入一样使用同目录临时文件和原子替换。

`AtomicTextStore` 统一稳定输出文件的写入语义。每日运行只替换 Agent 状态目录内的 `latest.html` 和 `latest.json`，时间戳 Markdown 与 TSV 历史仅追加，不执行自动清理。

`SnapshotStore` 把 TSV 当作有严格契约的单项目时序，读取和追加前都校验表头、取值范围、项目一致性与时间单调性。只有全部校验通过后才会原子替换历史文件。

`PortfolioRunService` 只在指定状态目录写入组合产物，不改动被扫描项目。组合门禁采用所有已识别项目中的最低健康分，防止平均分掩盖单个高风险项目；无项目时视为门禁失败。

`ProjectDiscovery` 在有界深度内递归寻找构建清单或 Git 根目录，并在发现阶段排除构建、依赖、版本控制和 Agent 状态树。返回路径统一解析为位于工作区真实路径之下的去重结果。

构建验证通过 `BuildCommandProvider` 与进程执行解耦。生产环境使用技术栈探测器，测试环境使用真实 Java 子进程夹具覆盖成功、失败、超时和大输出，同时不执行测试机上的任意第三方项目。

`--daily-verify` 是显式的动态验证编排入口。静态报告与构建结果分别落盘，构建 JSON 使用独立 schemaVersion 1 契约。`BuildEvidenceStore` 原子替换最新状态，同时将轻量 JSONL 摘要与完整日志分开归档，既能查询历史，也不会在每行重复大段构建输出。

`ActionPlanner` 将非信息类发现转换为稳定排序的行动队列。优先级先按严重度，再按类别和消息稳定排序；预计恢复分值与健康评分扣分保持一致，但报告明确标注为理论上限，最终改善必须通过重新扫描验证。

`CommandLine` 是公开 CLI 契约的单一注册点，负责命令最小参数校验、版本号与帮助文本，避免未知选项被误判为交互式工作区路径。

路径安全采用两层校验：`WorkspaceGuard` 同时检查词法规范化路径和现有文件的真实路径；`ProjectAnalyzer` 只接收真实路径仍位于项目根目录内的常规文件。这样即使工作区中存在指向外部的符号链接或目录联接，也不会读取目标内容。
