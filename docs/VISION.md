# 产品背景与目标

## 现实问题

学生和个人开发者通常同时维护课程作业、比赛项目、毕业设计和个人作品。它们散落在本机目录中，缺少统一 CI 或项目经理。常见后果包括：运行说明过期、测试缺失、TODO 长期积压、构建不可复现，以及临近答辩或面试时才发现项目无法运行。

## 用户与使用场景

- 学生：每天自动检查课程项目和毕业设计，提前暴露交付风险。
- 个人开发者：统一查看多个本地项目的维护优先级。
- 求职者：在展示项目之前检查文档、测试和可复现性。

## 产品原则

1. 本地优先：源码默认不离开电脑。
2. 证据优先：每个结论说明观察到了什么，而非输出模糊评价。
3. 行动优先：风险必须附带下一步建议。
4. 保守写入：分析只读，报告采用临时文件加原子移动落盘。
5. 可降级：核心能力不依赖 API 密钥、云服务或付费模型。

## 成功标准

- 对常见 Java、Node.js、Python、Rust 和 Go 项目给出基础体检。
- 在 10000 个文件以内完成有界扫描，不无限占用资源。
- 能在无人值守任务中生成报告并保留历史。
- 路径越界被测试明确拒绝。
