# 安全模型

## 信任边界

用户在启动时指定一个工作区。交互式文件工具只能接受相对路径；分析器只处理真实路径仍位于项目根目录内的常规文件。报告目录属于显式写入目标，其他分析行为保持只读。

`--init-config` 是唯一会直接写入待分析项目的引导命令。它先解析项目根的真实路径，再用操作系统 `CREATE_NEW` 语义创建配置；即使并发运行，已有配置也不会被覆盖。

Web 服务只绑定操作系统回环地址，并校验 HTTP `Host` 仅为 `127.0.0.1`、`localhost` 或 IPv6 回环，降低 DNS rebinding 将恶意站点映射到本地服务的风险。ZIP 上传只接受 `application/zip`，临时副本位于用户指定的启动工作区，分析结束或失败后清理；不会执行压缩包中的构建脚本。

## 已防护威胁

- 绝对路径访问。
- 使用 `..` 穿越工作区。
- 借助文件符号链接或 Windows 目录联接读取工作区外内容。
- 超大文本文件和过多文件造成的无界扫描。
- 敏感文件名提醒过程中读取凭据内容。
- JSON 输出中的引号、反斜杠、换行和控制字符注入。
- 报告或历史写入中断产生半文件。
- 同一状态目录的重叠日检相互覆盖历史或最新产物。
- ZIP 路径穿越、压缩炸弹式无界解压、超大单文件和过多条目。
- 使用非回环 `Host` 访问本地 Web API。

## 已知边界

- 这不是恶意软件扫描器，也不会判断源码是否可信。
- `--verify-build` 会执行项目提供的构建脚本，仅应对可信项目显式调用；其他命令不会自动触发它。
- 文件系统可能在检查后、读取前被其他进程替换；不要在敌对多用户目录中运行。
- 敏感文件检查只看文件名，不扫描内容，因此不会发现所有硬编码密钥。
- Windows 若禁止测试进程创建符号链接，相关 JUnit 用例会跳过；项目应另用目录联接执行平台集成验证。

## Windows 目录联接验证结果

在受限工作区内建立指向其外部兄弟目录的 Junction，然后执行 `读取 escape\\secret.txt`，预期结果为：

```text
[拒绝/失败] 符号链接指向工作区外部
```

任何能够输出目标文件内容的结果都应视为安全回归。
